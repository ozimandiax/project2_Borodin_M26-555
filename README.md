# Primitive DB

Учебный проект консольной базы данных на Python.
Реализованы управление таблицами и полный набор CRUD-операций с записями.
Структура таблиц и данные сохраняются в JSON между запусками, результаты выборок
выводятся через PrettyTable.
Для управления проектом используется uv, для проверки кода — Ruff.

## Требования

- Python 3.12 или новее. При необходимости uv загрузит Python автоматически.
- uv версии 0.5 или новее.
- Git.

Команды приведены для Windows CMD. Клонирование выполняйте из папки для проектов,
остальные команды — из корня проекта.

## Управление таблицами

| Команда | Назначение |
|---|---|
| `create_table <имя> <столбец:тип> ...` | Создать таблицу |
| `list_tables` | Показать список таблиц |
| `drop_table <имя>` | Удалить таблицу |
| `help` | Показать справку |
| `exit` | Выйти из приложения |

Поддерживаются типы столбцов `int`, `str`, `bool`. Системный столбец `ID:int`
автоматически добавляется первым. Если он указан явно, второго ID не создаётся.
Повторяющиеся имена столбцов, неверные типы и неверный тип ID отклоняются.

Пример команд внутри приложения:

```text
create_table users name:str age:int is_active:bool
list_tables
drop_table users
exit
```

При создании проверяется, что имя таблицы ещё не занято; при удалении — что таблица
существует. Неизвестные команды и неверные аргументы не завершают приложение.
Имена с пробелами можно заключать в кавычки, например:

```text
create_table "project users" name:str
drop_table "project users"
```

## CRUD-операции

| Команда | Назначение |
|---|---|
| `insert into <таблица> values (<значение>, ...)` | Добавить запись |
| `select from <таблица>` | Вывести все записи |
| `select from <таблица> where <столбец> = <значение>` | Выбрать записи по условию |
| `update <таблица> set <столбец> = <значение> where <столбец> = <значение>` | Обновить подходящие записи |
| `delete from <таблица> where <столбец> = <значение>` | Удалить подходящие записи |
| `info <таблица>` | Показать схему и количество записей |

В `insert` передаются все значения, кроме системного ID. ID генерируется
автоматически и недоступен для изменения через `update`.

Правила значений:

- `str` — строка в одинарных или двойных кавычках;
- `int` — целое число без кавычек, в том числе отрицательное;
- `bool` — `true` или `false` без кавычек.

Например, `"28"` остаётся строкой, а `28` является числом. Строки могут содержать
пробелы, запятые, скобки, знак `=` и слова `where`/`set`. Двойную кавычку внутри
строки в двойных кавычках можно экранировать: `"He said \"Hello\""`.

Условие `where` поддерживает одно равенство. Для `update` и `delete` оно
обязательно. В `set` можно перечислить несколько полей через запятую.
Имена столбцов, количество значений и типы проверяются до сохранения изменений.

Полный пример:

```text
create_table users name:str age:int is_active:bool
insert into users values ("Sergei", 28, true)
insert into users values ("Anna, Maria", 25, false)
select from users
select from users where age = 28
update users set age = 29, is_active = false where name = "Sergei"
select from users where ID = 1
info users
delete from users where ID = 1
select from users
drop_table users
exit
```

Если подходящих записей нет, `update` и `delete` сообщают об этом. Пустая выборка
`select` выводится с заголовками столбцов.

## Хранение метаданных и записей

Метаданные хранятся в `db_meta.json` в текущей рабочей папке. Если файла ещё нет,
используется пустой словарь. После успешного создания или удаления таблицы изменения
сохраняются. При следующем запуске из той же папки таблицы остаются доступны.

Пример структуры файла:

```json
{
    "users": ["ID:int", "name:str", "age:int", "is_active:bool"]
}
```

Записи каждой таблицы хранятся отдельно: например, `data/users.json`.
Файл содержит массив объектов:

```json
[
    {"ID": 1, "name": "Sergei", "age": 28, "is_active": true}
]
```

После `insert`, `update` и `delete` данные сохраняются. `drop_table` удаляет
метаданные и файл записей; повторное создание таблицы начинает работу с пустыми
данными. Имена таблиц должны быть допустимыми именами файлов Windows;
разделители пути запрещены, пробелы внутри имени и кириллица поддерживаются.

Повреждённый JSON вызывает сообщение об ошибке и не заменяется пустой базой.
Файл метаданных и папка `data/` исключены из Git.

```bat
uv build
```

## Установка собранного пакета

Если виртуальное окружение активировано, сначала выполните `deactivate`,
чтобы проверить команду из отдельно установленного пакета.

```bat
uv tool install --force --reinstall dist\primitive_db-0.4.0-py3-none-any.whl
database
```

Если uv сообщает, что каталог инструментов отсутствует в `PATH`, выполните
`uv tool update-shell` и перезапустите терминал.
